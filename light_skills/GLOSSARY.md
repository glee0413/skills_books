# 术语表

这是全书译名的唯一事实源。新增术语时先在这里登记，再在译文里使用。首次出现可以给英文原词，之后按这里的译法。

| 英文 | 中文 | 说明 |
|---|---|---|
| skill | 技能 | 指一个可被 agent 加载的 `SKILL.md`，不译成“技巧”。 |
| agent | 智能体（agent） | 首次出现给英文，之后可用 agent。 |
| harness | 运行框架（harness） | 承载 agent 的宿主或运行时。 |
| context window | 上下文窗口 | 模型一次能看到的上下文容量。 |
| subagent | 子代理 | 由主代理派生的独立执行单元。 |
| spec | 规格（spec） | 对要构建内容的明确描述。 |
| ticket | 工单 | 可执行的工作单元。 |
| issue | 议题（issue） | 议题跟踪器中的条目，与工单区分。 |
| issue tracker | 议题跟踪器 | 承载 issue 的工具。 |
| triage | 分诊 | 对进入的 issue 分类、补全、排优先级。 |
| seam | 接缝 | 观察行为而不深入内部的公共边界。 |
| tracer bullet | 曳光弹 | 先打通一条端到端路径的最小实现。 |
| deep module | 深模块 | 小接口背后隐藏大量行为的模块。 |
| grilling | 追问（grilling） | 连续提问，直到设计树的每个分支都被解决。 |
| frontier | 前沿（frontier） | 当前前置条件已满足、可以立即提问的决策集合。 |
| workflow | 工作流 | 一串按顺序执行的步骤。 |
| gate | 门禁 | 必须通过才能进入下一步的检查。 |
| review | 审查 | 对代码、计划、设计或文档的检查。 |
| ship | 发布（ship） | 把改动验证、推送并交付出去。 |
| retro | 复盘 | 回看一次工作，找出环境或流程的改进点。 |
| prototype | 原型 | 为回答一个问题而写的可丢弃代码。 |
| decision ticket | 决策工单 | wayfinder 中承载一个问题、产出决策的工单。 |
| model-invoked | 模型可调用 | 模型可以在任务匹配时自动触发。 |
| user-invoked | 用户调用 | 只能由人输入命令触发。 |
| prompt | 提示词 | 发给模型的输入文本。 |
| plan mode | 计划模式 | 先形成计划、再执行的工作模式。 |
| red-green | 红绿 | 先写失败测试，再写最小实现让它通过。 |
| vertical slice | 垂直切片 | 一次打通一个行为从接口到实现的薄片。 |
| feedback loop | 反馈回路 | 能快速告诉你改动是否有效的检查。 |
| domain model | 领域模型 | 对业务概念及其关系的结构化理解。 |
| ADR | 架构决策记录（ADR） | 记录一个重要技术决策及其原因。 |
| glossary | 术语表 | 项目内统一使用的词汇表。 |
| design tree | 设计树 | 一个决策分支到后续决策的结构。 |
| round | 轮次 | 一次提出当前前沿全部问题的追问批次。 |
| taste | 品味 | 对设计取舍的偏好，常通过选择和反馈积累。 |
