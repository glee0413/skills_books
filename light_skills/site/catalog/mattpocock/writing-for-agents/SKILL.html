为 agent 写文档的通用参考，适用于创建或修改技能，以及编写 AGENTS.md、CLAUDE.md 或任何被指针指向的文档。

这是写给 agent 消费的任何文档的参考：一个技能、一份 AGENTS.md / CLAUDE.md、一篇被指针指向的文档。打包方式各不相同，写法却相同：同样的几个杠杆让每一份都变得可预测，因为 agent 每次运行走的是同一套_过程_，而不是产出同样的输出。

当你写的文档是一个技能时，读 SKILL-MECHANICS.md，了解 frontmatter、调用方式的选择和路由技能。

上下文指针

上下文指针（context pointer） 是留在 agent 上下文里的一个引用，它指明某份上下文之外的材料，并编码了够到那份材料的条件。技能的 description 是一个指针；AGENTS.md 里点名某篇文档的一行是同一个对象。决定 agent 何时、以及多可靠地去够材料的是指针的_措辞_，不是它的目标。一个必须命中的目标躲在措辞软弱的指针后面，就是方差缺陷：先把措辞磨利，只有在磨不利时才把材料内联进来。

指针干两件事：说明材料是什么，并列出应当触发去够它的分支（一个分支就是文档处理的一种不同情形，所以不同的运行会走不同的路径）。一个常驻加载的指针，每个词在每一轮都要付出代价，所以它比正文更需要狠心修剪：

  • 把领头词前置：指针正是它发挥触发作用的地方。
  • 每个分支一个触发词。 给同一个分支换个名字的同义词，是把一个分支写了两遍；把它们合并，只保留真正不同的分支。
  • 砍掉正文已经承载的身份信息。

两种负载

你添加的每份文档和每个指针，都在花掉两种预算之一：

  • 上下文负载（context load） 是常驻材料对 agent 上下文窗口的开销：AGENTS.md 的一行、技能的 description、任何每一轮都待在上下文里的东西，无论是否触发都在消耗 token 和注意力。
  • 认知负载（cognitive load） 是对人的开销：有哪些文档存在、什么时候该去够哪一份。人就是索引。它不是要被最小化的成本：它是人的能动性的价格；在人做判断重要的地方花它，在不重要的地方去掉它。

只通过指针才能到达的材料，逃掉了上下文负载，代价是指针自己那一行；完全没有指针的材料，则完全靠认知负载承载。

信息层级

文档由两类内容构成：步骤（agent 按顺序执行的动作）和参考（按需查阅的定义、规则、事实）。两者可以自由混合：全是步骤（一份配方）、全是参考（一份审查的规则、这个技能），或者两者都有。核心决策是每一块内容落在信息层级的哪个位置——这是一架按“agent 多急需这份材料”排序的梯子：

  1. 文件内步骤是主层级：agent 按顺序做什么。
  2. 文件内参考按需查阅。常常是一组合法平铺的同级内容（一份审查的每条规则都在同一级），这是不错的安排，不是坏味道。
  3. 外置参考（disclosed reference） 被推到单独的文件里，通过上下文指针到达，只在指针触发时加载。范围可以从同一目录里的兄弟文件，一直到存放在任何地方、任何文档都能指向的完全外部参考。

往下推得太少，顶层就会臃肿；推得太多，又会把 agent 真正需要的材料藏起来。这个张力就是整个决策。

渐进披露（progressive disclosure） 是沿梯子向下移动（移出主文件、放到指针后面），让顶层保持可读。它主要不是 token 优化：它是保护这套层级的方式。分支是检验披露最干净的标准：每个分支都需要的内联，只有部分分支才会够到的推到指针后面。当文档里有步骤时，本该被披露出来的文件内参考会把这些步骤埋掉，让“注意到它们”变成抛硬币：这是一个方差杠杆，不只是可读性杠杆。

就近放置（co-location） 是文件内的搭档：梯子决定一块内容落在_多深_，就近放置决定它落下之后_和谁挨着_。把一个概念的定义、规则和注意事项放在同一个标题下，而不是散落各处，这样读其中一部分就会把邻居一起带过来。检验标准：文档读起来应该像为 agent 写的文档。成组放置的材料读起来就是这样；散落的材料不是。（这与重复不同：重复是在两个地方重复同一个意思；散落是把一个意思撕成多份。）

蔓延（sprawl） 是这里的失败模式：文档就是太长了，即使每一行都有效且独特。注意力在过量内容上被摊薄，而且每多一行，就多一行需要维持相关性。解药就是那架梯子：把参考披露到指针后面，并按分支或序列拆分，让每条路径只携带自己需要的东西。

步骤与完成标准

每个步骤都以一个完成标准收尾，也就是告诉 agent 工作已经做完的条件。两个属性让它成为杠杆：

  • 清晰度：agent 能否分辨做完和没做完？模糊的边界（“达成理解”）会诱发提前完成：在真正做完之前就结束这一步，注意力滑向_已经做完_。前方仍然可见的步骤（完成后的后续步骤）提供拉力；标准的清晰度则是阻力。按顺序防守：先把边界磨利（局部且便宜）；只有它确实模糊到无法再降，_而且_你观察到抢跑的冲动时，才通过拆分序列把后面的步骤藏起来。隐藏只有在跨越真实的上下文边界时才有效（一次交接，或一次子代理派发；内联调用会把这些后续步骤留在上下文里，什么也清不掉）。
  • 要求强度（demand）：它要求多少。“每个被修改的模型都有交代”逼出彻底的工作，而“产出一份变更清单”不会。要求强度驱动探底工作（legwork）——agent 在工作内部做的挖掘，它潜藏在措辞里，而不是写成单独的一步；它也不受步骤约束：“每条规则都应用到位”约束的是一整片平铺参考，正如“每一步都做完”约束的是一个序列，这就是全参考文档也能带上穷尽性门槛的原因。

最强的标准既可检查，又穷尽。

何时拆分

把一份文档拆成两份，要花掉两种负载之一，所以只有当这刀切得值时才拆：

  • 按序列拆：在一串步骤中，如果完成后的后续步骤会诱使 agent 抢跑眼前这一步，就拆开。把它们挡在视野之外，能让当前任务上多花些探底工作。要提防反过来：合并序列会把每一步的后续步骤暴露给接下来要做的事，诱发提前完成。
  • 按调用方式拆，技能专属：见 SKILL-MECHANICS.md。

引导词

引导词（leading word） 是一个紧凑的概念，它本来就活在模型的预训练里，agent 在跑这份文档时用它来思考（lesson、fog of war、tracer bullets）。它作为 token 被重复，而不是作为句子，因此累积出一个分布式的定义，用最少的 token 锚定一整片行为区域，靠的是招募模型已经持有的先验。自造词也行，只要你定义清楚，但自造词招募不到任何先验：预训练词免费给你的东西，你要用定义 token 去付；优先伸手去够已有的词。

它锚定两处。在正文里，锚定_执行_：这个词一出现，agent 每次都会伸手去拿同一种行为；在平铺参考里，它把注意力聚焦到某一类要找的东西上。在指针里，锚定_调用_：当同一个词同时活在你的提示词、你的文档和你的代码库里时，agent 会把这种共享语言和那份材料联系起来，更可靠地够到它。

去寻找用引导词重构的机会。三个地方各写一遍的三元组；一个花一整句来指手画脚某个想法的指针。每一处都是急切希望坍缩成单个 token 的段落：

  • “快、确定、低开销” → tight（一个 tight 循环）。
  • “一个你信得过的循环” → red，把一个模糊的门禁变成一个二值可观察状态（循环面对这个 bug 要么变 red，要么不变）。

你能赢两次：更少的 token，以及给 agent 一个更锋利的挂钩来挂它的思考。假设每份文档都带着一些能被引导词替换掉的复述。去把它们找出来。

否定（negation） 是紧挨着这个杠杆的失败模式：用禁令来操控，会把被禁止的行为拖进上下文，让它变得_更_可用，而不是更不可用。别去想大象，于是满脑子只有大象；否定是一个弱修饰语，被强激活的概念直接压过，所以这条禁令有一半读起来像是在指示你去做那件事。请提示正面：把目标行为说出来（“写一行注释”），让被禁的那个从未被说出。禁令只有在无法用正面表述的硬护栏里才配有一席之地；即便那时，也要把它和正面目标配对，让注意力落在该做什么上。

修剪

  • 让每个意思只有唯一事实源：一个权威位置，这样改行为就是改一处。重复（同一个意思出现在不止一个地方）要付出维护和 token 成本，还会把某个意思在梯子上的显眼程度抬到超过它真实的层级。（它是引导词的意外反面：引导词故意重复 token，从不重复意思。）
  • 环境也是事实源（package.json 的 scripts、配置文件、目录布局、--help 输出），而重述环境的文档是一份缓存：一次查找的副本，只有当查找很昂贵时才值回它的加载成本。缓存 agent 看一圈也找不到的东西：没写下来的约定、某个选择背后的理由、任何配置都不愿承认的坑。把一文件、一命令就能查到的内容留给环境，在那里它们不会过期。
  • 逐行检查相关性：它是否仍然和这份文档要做的事有关？一行会失去相关性，或者是从来不和任务沾边（纯粹的说教，或者一个本该被披露出去的分支），或者随着它描述的行为或世界变化而过期。更短的文档更容易保持相关。没有修剪纪律，默认的结局就是沉积（sediment）：一层层过时的东西安顿下来，因为添加感觉安全、删除感觉冒险，直到你必须打钻穿透它们才能找到还活着的东西。
  • 逐句寻找空操作（no-op）：模型默认就已经遵守的指令，付出了加载成本却什么也没说。检验标准（它是否改变了相对默认行为的行为？）是相对模型而非相对读者的：两个人为一个空操作争论，其实是在为默认行为争论，解决方式是把文档跑一遍，而不是辩论。当一句话没通过检验，删掉整句，而不是删掉几个词。这个检验也适用于给引导词打分：一个弱到压不过默认行为的词（agent 本来就大致彻底时，你说 be thorough）就是空操作，解药是换一个更强的词（relentless），而不是换一种技巧。
