# 逻辑原型

一个单独的、自包含的 HTML 文件（一份**可分享的演示**），让任何人通过点击按钮来驱动一个状态模型。当问题关于**业务逻辑、状态转换或数据形状**时使用它：这类东西在纸上看着合理，只有拿真实情况推一遍才会觉得不对。

因为它是一个文件、什么都不用安装，你可以把它交给非开发者（设计师、PM、领域专家），让他们自己感受这个模型。所以它说的是他们的语言，而不是代码的语言。

## 什么时候这是正确的形状

- “我不确定这个状态机能不能处理先 X 再 Y 的边缘情况。”
- “这个数据模型真的能让我表示……的情况吗？”
- “我想在写之前先摸清楚 API 应该长什么样。”
- 任何有人想**按按钮、看状态变化**的场景。

如果问题是“这东西应该长什么样”，那这是错误的分支。用 [UI.md](ui.md)。

## 过程

### 1. 陈述问题

写代码之前，先写下你要做原型的是什么状态模型、要回答什么问题。一段话，放在演示的顶部（放在可见的引言里，而不只是注释里）。回答错问题的逻辑原型是纯粹的浪费，所以要把问题写明确，以便之后核对——无论用户是现在看着，还是离开后回来。

### 2. 把逻辑隔离在可移植的模块里

把真正的逻辑（回答问题的那个部分）放在单个 `<script>` 块里，写成一个小而纯的模块，之后可以被拎出来放进真实代码库。它周围的页面是可丢弃的；这个模块不是。

正确的形状取决于问题：

- **一个纯 reducer**：`(state, action) => state`。当动作是离散事件、状态是单一值时合适。
- **一个状态机**：显式的状态和转换。当“现在到底哪些动作合法”也是问题的一部分时合适。
- **一小组纯函数**，作用于一个普通数据类型。当没有隐含的当前状态、只有转换时合适。
- **一个带清晰方法面的类或模块**，当逻辑确实拥有持续的内部控制状态时。

选最契合所问问题的形状，*而不是*最容易接到页面上的形状。保持纯粹：不要 DOM，不要 `document`，不要让按钮处理器伸进去。页面调用它；没有东西反向流动。这正是原型在寿命结束后仍然有用的原因：问题一旦回答完，经验证的 reducer / 状态机 / 函数集就能自己提升为真实模块。

### 3. 构建可分享的 HTML 文件

一个文件，纯 HTML/CSS/JS：不用框架，不用打包器，不用服务器，所有东西内联，双击就能打开，也能经受邮件转发。任何人打开它都应该能跑起来。

为 非开发者而写。每个标签都用**领域语言**，不是代码：按钮和状态读起来像业务，而不是 reducer。用平实的话解释正在发生什么。

用清晰的层次自上而下布局：

1. **标题和一句话说明**，讲清这个演示让你探索什么（第 1 步里的问题）。
2. **当前状态**：完整的相关状态，渲染成可读的面板（带标签的字段，而不是原始 JSON 转储），每次点击后重新渲染，让变化可见。在有助于非开发者跟上时，点出刚刚变化了什么。
3. **自由操作按钮**：每个动作一个按钮，始终可用，让任何人都能按任意顺序摆弄模型。每次点击派发对应动作并重新渲染状态。
4. **引导式演练**：一组**场景**，每个标签页一个。每个标签页里有一段简短平实的场景说明（它设置的情境，以及要观察什么），下面是为该场景排好序的**待按按钮**。每一步都是真正的按钮：点击它执行该动作并进入下一步。开始演练时会重置到已知的初始状态，这样场景每次运行方式都一致。

选择能展示棘手情况的场景，也就是那些在纸上难以推理的：正常路径、一个刁钻的边缘情况、一次对本来不该允许之事的尝试。

保持美观但克制：干净的排版、充裕的间距、一个强调色。不要动画，不要花招：任何与状态和按钮争夺注意力的东西都不要。

### 4. 交给对方

把文件发给他们，或者替他们打开。他们有空时会点过演练和自由操作；有趣的时刻是他们说“等等，这不应该可能”或者“嗯，我以为 X 会不一样”的时候；这些是**想法**里的 bug，而这正是重点。如果他们想要新动作或新场景，就加上。原型会演化。

### 5. 留存答案和原型

原型回答了它的问题之后，先留存答案，再按 [SKILL](SKILL.md) 描述的方式留存原型。逻辑特有的映射是：经验证的 reducer / 状态机 / 函数集提升为真实模块（决策被吸收）；HTML 外壳随原型一起进入可丢弃分支，那分支把原型作为一手资料保存，而因为它是一个自包含文件，在那里重新运行仍然毫不费力。

## 反模式

- **不要加测试。** 需要测试的原型就不再是原型。
- **不要接真实数据库。** 用内存状态，除非问题专门关于持久化。
- **不要泛化。** 不要“万一以后要支持 X 呢”。原型只回答一个问题。
- **不要把逻辑和页面搅在一起。** 如果纯模块引用了 DOM、`document` 或按钮处理器，它就不再能被拎出来了。让页面保持为纯模块之上的薄壳。
- **不要去找框架、打包器或服务器。** 收件人双击打开的一个文件；React 应用或开发服务器会毁掉“可分享”。
- **不要把 HTML 外壳发布到生产。** 页面是为手工点击而优化的。它背后的逻辑模块才是值得留下的部分。
